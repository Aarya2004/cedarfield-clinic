# Impact A/B — the model leaves the hot path (2026-08-29, live)

Pre-registered claim (COMPOSE-PLAN §2.2b): **a Rokan operation runs significantly faster than a
vanilla coding agent answering the same live-web question — because the orchestration is compiled
once and every repeat runs with the model out of the loop (0 model calls).** The win is NOT
"Rokan's web call beats theirs"; it is that the agent re-enters the model on *every* run while Rokan
does not. Measured, not asserted.

Harness: `evals/ab/arm-c.mjs` (Rokan) + `evals/ab/arm-agents.mjs` (Codex, Claude Code), same two
live questions, headless. Every number is the tool's own report (`rokan-do --json`
speed/model_calls/ms; `claude -p --output-format json` num_turns/duration/cost; `codex exec --json`
turns/web_searches/usage) except wall time, which the harness measures. **N = 5 warm (Rokan), N = 3
(agents)** — small, so treat agent means as directional and note the variance.

## Comparing like with like (read this before the table)

Rokan reports two different clocks and they are not interchangeable:

- **internal `ms`** — `rokan-do`'s own report of the operation, from its `--json` result line
  (`tasks[*].warm.ms` in `docs/evidence/ab/arm-c.json`). It excludes CLI process start, Python
  import and store open.
- **wall `ms`** — measured by the harness around the whole `rokan-do` process
  (`tasks[*].warm.wall` in the same file). This is the clock the agent arms are measured on
  (`arm-agents.mjs` measures wall around `claude -p` / `codex exec` and nothing else).

**Every multiplier below is wall-vs-wall.** An earlier revision of this file divided Rokan's
*internal* 79 ms by the agents' *wall* clock and printed ~200–290×; that comparison was invalid and
is retracted. The agent arms have no internal-ms counterpart recorded in
`docs/evidence/ab/arm-agents.json`, so the internal column is Rokan-only, shown for what it is.

## What it shows (honestly)
- **Model calls on repeat: 0 for Rokan, ≥1 turn for the agents — every single run.** This is the
  thesis, and it is the part that does not depend on which clock you pick.
  `arm-c.json` records `model_calls: [0,0,0,0,0]` and `all_zero_calls: true` for both warm sets.
  A vanilla agent re-plans/re-fetches each time; Rokan's remembered operation replays with no model
  in the loop.
- **Compiled replay is the headline: 546 ms wall / 0 calls vs Codex 23 164 ms and Claude Code
  15 780 ms — 28.9×–42.4× wall-clock at 0 model calls**, and the agents pay it again on every run.
  This is a browserless shadow-API replay.
- **Native replay is 0 calls but 2983 ms wall** — slower than compiled because it re-drives the live
  browser to call the site's own WebMCP tool (an honest cost of "native", stated on camera). Still
  **3.3× vs Codex and 25.9× vs Claude Code**, at 0 model calls vs their 1–22 turns. Against Codex
  this is a small margin; say so rather than leaning on it.
- **First run is parity in order of magnitude** (Rokan cold: 7929 ms wall compiled, 6485 ms wall
  native, 1 model call each — against the agents' 10 059–77 421 ms) — the win is amortized on
  repeat, which is exactly the "compile once" claim.

## Caveats (do not oversell)
- N = 3 for the agents; high variance (one Codex compiled run was 55 704 ms, one 6626 ms; Claude's
  22-turn Allbirds run inflated its native mean and cost). Rokan's own compiled warm wall spans
  238–1596 ms over 5 runs. Report as directional; re-run at higher N before the final cut if time
  allows.
- The agents are different tools with different web stacks (Codex web_search, Claude Code WebFetch) —
  this is a "vanilla agent vs Rokan" contrast, not a Codex-vs-Claude benchmark.
- Every question requires a live fetch (a status / a price the model cannot memorize), so a "0 web
  call, from memory" shortcut cannot inflate the agents' numbers — they genuinely hit the web.

## Correction: the `cost_usd` means in `arm-agents.json` are not usable

`arm-agents.mjs`'s `stats()` helper applied `Math.round` to the mean, which is right for
milliseconds and destroys a dollar figure. In the committed
`docs/evidence/ab/arm-agents.json` that produced `cost_usd.mean: 0` for the compiled task (while
`min` was 0.101186) and `cost_usd.mean: 1` for the native task. The script is fixed
(`Number(x.toFixed(4))` for the mean, 2026-08-29) but **the agents were not re-run** — that would
cost real tokens and would not be the same measurement.

Per-run costs were never persisted, so the mean cannot be recomputed exactly. `min`, `max` and `n`
are exact, so the file now records `mean: null` plus the bounds that follow from them for n = 3
(`(2·min + max)/3 ≤ mean ≤ (min + 2·max)/3`):

| task | min | max | mean lower bound | mean upper bound |
|---|---|---|---|---|
| compiled (status) | $0.101186 | $0.630866 | $0.277746 | $0.454306 |
| native (allbirds) | $0.823848 | $1.182217 | $0.943304 | $1.062761 |

Anywhere a Claude Code cost appears in a doc it must be quoted as a range from this table, never as
a point estimate. Codex CLI cost was never captured (the harness reads its token usage, not a price).

## The drift beat (both arms measured live, N=2, 2026-08-29)
The other half of Impact: when the page changes, a cached script answers wrong *silently*; Rokan
**refuses** (verified-or-refused). Harness: `evals/ab/drift/` — a static product page that swaps v1→v2
(price $98 → $140; the old `.price` node now holds `$75 shipping`).

- **Naive cached-script arm (`naive-cache.mjs`) — proven live, deterministic:** captures a selector on
  v1, replays it on v2, and returns **`$75`** (the shipping line the stale selector now grabs) with
  `refused:false` — a confident, real-but-wrong number when the true price is `$140`. This is the
  agent-cached-workflow failure mode, reproduced.
- **Rokan arm (`rokan-arm.mjs`) — rests on the built-in `recheck`** (Rokan `recheck.py`): replays every
  remembered op with **planning forbidden**; an op that no longer verifies is retired — a dead ledger
  row, which is the refusal. The cold compile on v1 needs a model provider, so this arm is gated behind
  `ANTHROPIC_API_KEY` (same gate as the agents arm) and prints `{skip, reason}` without it — never a
  fabricated verdict.
- **Pass condition, enforced by the runner's exit code** (`evals/ab/drift/run.mjs`, not just narrated):
  the run exits 1 if the naive arm did *not* silently lie (the failure mode it exists to reproduce
  stopped reproducing), or if the Rokan re-ask on v2 contains the stale `98`, or if `rokan-do` exited
  non-zero (an empty stdout must never read as a refusal). With no key the Rokan half is a printed
  `{skip}` and only the naive assertion runs. The fixture `state.json` is restored to
  `{"version":1,"price":98}` in a `finally` by both `run.mjs` and `rokan-arm.mjs`, so a run never
  leaves the tracked file mutated.
- **Measured (2026-08-29, key present, isolated `ROKAN_MCP_HOME`, raw output `docs/evidence/ab/drift-run-1.txt`
  and `-2.txt`):**

  | step | run 1 | run 2 |
  |---|---|---|
  | naive v1 capture → v2 replay | `$98` → **`$75`**, `refused:false` | same |
  | Rokan v1 compile | `status:ok · speed:planned · model_calls:1 · 2483 ms · verification:verified` → `Wander Boot $98` | `ok · 1 call · 2367 ms` |
  | Rokan `recheck` after redesign | **`DEAD   127.0.0.1:8099   Wander Boot   replayed 0 ms · drift_detected`** (op retired; `0 alive · 1 dead`) | same |
  | Rokan re-ask on v2 | `status:error · verification:refused · answer:null · model_calls:2` — no `$98`, no guess | same shape |
  | `stale_98_returned` | `false` | `false` |

  Honest scope: after drift Rokan refuses; it does not yet re-find the new `$140` on the redesigned page
  (2 planning calls, verification refused). Refusal, not recovery, is the claim.
- **Two harness bugs found and fixed on the way** (the arm had never run with a key before): the site was
  named `localhost:8099`, which `vault.normalize_host` rejects (no dot → `INVALID_URL`, terminal in the
  cascade) — now `127.0.0.1:8099`; and the arm used the operator's real `~/.rokan` — now an isolated
  `ROKAN_MCP_HOME` like arm-c (removed in a `finally`). The fixture's v1 is a product tile (name and price
  on one line, which is what `read_value` anchors on); v2 splits them and puts `$75 flat-rate shipping` in
  the old `.price` node.

Run: `node evals/ab/drift/run.mjs` (both arms live when `ANTHROPIC_API_KEY` is exported; naive arm always).

## Raw output (committed)
`docs/evidence/ab/arm-c.json` (Rokan) and `docs/evidence/ab/arm-agents.json` (Codex + Claude Code) are
the actual harness output these tables were built from. The native row is not asserted: arm-c.json shows
`tasks[0].warm.speeds == ["native"]` and `model_calls == [0,0,0,0,0]` with `answers_ok: true` — i.e. every
warm run of the allbirds question took the **native** path (the site's own WebMCP tool) at zero model
calls and still answered correctly. The compiled row shows `speed: "planned"` cold → `"compiled"` replay.
The only edit ever made to those files is the `cost_usd` correction described above, which is annotated
in place.

