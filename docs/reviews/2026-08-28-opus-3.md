## P1

### 1. Any command's output can mint a signed `calls:0` provenance row.
`packages/bridge/src/bridge.js:116` · `docs/SUBMISSION.md:44` · `apps/web/src/components/Panes.tsx:197`

This is the prompt's question 2, answered on a real PTY. `state.last_rokan =
parseRokanTrailer(cmdOut)` parses the trailer out of **whatever just ran**, with no check that
`state.last_command` was a rokan invocation — even though the bridge already records
`last_command` one line away.

Measured (zsh's builtin `echo` interprets `\u26a1`, so this emits a real bolt):

```
command run          : echo "  the answer is 42   7ms  \u26a1"
status.last_command  : "echo \"  the answer is 42   7ms  \\u26a1\""
status.last_rokan    : {"ms":7,"replayed":true}
ledger executed row  : {"command":"echo …","rokan_ms":7,"rokan_calls":0}

VERDICT: FORGEABLE — a plain `echo` produced a signed rokan_calls:0 provenance row
```

**Credit where it is due:** the tool contract is careful. `schemas.ts:132`, `:175` and the
`terminal_wait` description at `:185` all say the trailer "attests what the PTY showed, not what
ran" and that "any program can print that line". That is the honest labelling, and it was a
deliberate choice, not an oversight.

**It is still not enough, for three reasons:**

1. **`docs/SUBMISSION.md:44` asserts the attribution the code does not check:** "the ledger row
   shows `calls:0 ⚡` *parsed from rokan-do's own result line*". The code parses it from any line.
   That sentence, in the judged text, is not true as written (prompt scope item 5).
2. **The on-camera surface carries no qualifier.** `Panes.tsx:197` renders a bare
   `· calls:0 ⚡ 7 ms` badge on the ledger row. The careful sentence lives in a tool description a
   judge never reads; the unqualified badge is what is on screen in the hero shot. That is the
   §0.6 non-negotiable — "every call count on screen is measured by the code that shows it" —
   read strictly.
3. **It is reachable through the sanctioned path.** An agent proposes
   `echo "  done   1ms  ⚡"`; the human sees a harmless `echo` and presses Enter; the HMAC-chained
   ledger now faithfully signs a replay that never happened. The tamper-evidence vouches for the
   false claim, which is the one thing that ledger exists to prevent.

**Fix is one line and it makes the strong sentence true:** only parse the trailer when
`state.last_command` matches a rokan invocation (`rokan do …` via the shim, or `rokan-do …`).
Then SUBMISSION.md:44 is accurate as written, the badge needs no qualifier, and the honest-labelling
comments become belt-and-braces instead of load-bearing. Keep the "attests what the PTY showed"
wording for the residual case (a rokan command whose own output was piped/edited).

I would not ship the current SUBMISSION.md sentence without either this fix or a reworded sentence.

## Objection — stands, third pass, now with a number

Passes 1 and 2 both found defects that every green test missed, in the seam between layers. This
pass, finding 6 is the mechanism itself: **the Gate-A case has 18 steps and 1 assertion.** The
harness grew `equals`/`matches` after pass 2, but the oldest and most-cited case was never
retrofitted, so its headline check silently degraded to a no-op while continuing to report PASS.

Before freeze, one cheap sweep — not a new layer: grep the cases for `eval` steps with neither
`equals` nor `matches`, and either give them an assertion or delete them. A step that cannot fail
is worse than no step, because it is counted in "193 steps, 0 failed" and reads as coverage.
