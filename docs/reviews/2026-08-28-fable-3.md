## P1

### F1. `calls:0 ⚡` is attributed to whatever the PTY printed, not to a `rokan` command line — the ledger, the hero beat and the evals show an `echo` as a zero-call replay
`packages/bridge/src/bridge.js:116` (`state.last_rokan = parseRokanTrailer(cmdOut)` — unconditional) ·
`apps/web/src/components/Panes.tsx:196` (`· calls:0 ⚡ …` on any `executed_step` row) ·
`evals/cases/terminal-rokan-trailer.json:3` and `packages/bridge/test/smoke.mjs` ("rokan trailer" ×3) — lane C.

Answer to the pass-3 question: **the bridge must attribute.** SECURITY.md §4 now says honestly that
"any program can print that line", but that sentence is in a doc; the *screen* (ledger pane), the
hero shot (PLAN §1 / DEMO 0:20 `calls:0`), SUBMISSION ("the ledger row shows `calls:0 ⚡` parsed from
rokan-do's own result line") and the evals folder Gao reads all present the number as Rokan's. A
forged tool made of `cat notes.txt` whose file contains `  x   1ms  ⚡` shows `calls:0 ⚡` on camera.
PLAN §0.6 is a non-negotiable: a printed line is not "measured by the code that shows it".

Measured (this gate run, real PTY): smoke `echo '  GitHub blocks … 312ms  ⚡'` → `last_rokan {ms:312,
replayed:true}` → PASS; `terminal-rokan-trailer.json` step 3 `echo '  All Systems Operational   312ms  ⚡'`
→ `terminal_wait.rokan.calls === 0` → PASS. Both cases pass *because* an `echo` is accepted.

Fix (≈ 15 lines, bridge only): the bridge already knows the command line from OSC 7331
(`state.last_command`). Parse the trailer only when
`/^\s*(?:command\s+|exec\s+)?(?:rokan|rokan-do)\b/.test(state.last_command ?? '')`; otherwise
`last_rokan = null`. Keep the `echo` cases as **negative** tests (`rokan === undefined`,
`last_rokan === null`) and add one positive case that runs the real shim
(`rokan do "what is the current status at githubstatus.com"` is seeded on the demo Mac — FIELD-NOTES R3;
in CI, a `rokan-do` stub on PATH that prints the line is fine, because the *command line* is then
honest). Update SECURITY §4 to "attributed to a `rokan`/`rokan-do` command line by the bridge".
