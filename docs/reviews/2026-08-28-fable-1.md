## P1

### F1. Redaction: `kv_secret` needs a word boundary *before* the keyword, so every `PREFIX_TOKEN=` form leaks
`apps/web/src/lib/webmcp/redact.ts:48` — lane C.

`\b((?:pass(?:word|wd)?|pwd|token|secret|api[_-]?key|…)[A-Za-z0-9_-]*)` — the `\b` sits before the
keyword, and `_` is a word character, so `AWS_SECRET_ACCESS_KEY`, `VERCEL_TOKEN`, `PGPASSWORD`,
`CLOUDFLARE_API_TOKEN`, `npm_token`, `MYSQL_PWD` never match. The JSON form `"password": "x"` fails on
the closing quote before `:`; `TOKEN="a b"` fails on the space; URL credentials and `sk_live_` /
`rk_live_` / `AIza…` have no rule at all.

Measured (`scratchpad/redact-probe.ts`, 29 lines, N=1):
```
LEAK  AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
LEAK  export AWS_SECRET_ACCESS_KEY=…            LEAK  PGPASSWORD=hunter2 psql
LEAK  MYSQL_PWD=hunter2                          LEAK  {"password": "hunter2"}
LEAK  "api_key": "abc123"                        LEAK  DATABASE_URL=postgres://admin:s3cretpw@db…
LEAK  psql --password hunter2                    LEAK  STRIPE_SECRET_KEY=sk_live_abcdef…
LEAK  GOOGLE_API_KEY=AIzaSyA-…                   LEAK  VERCEL_TOKEN=Abcdefghijklmnopqrstuvwx
LEAK  CLOUDFLARE_API_TOKEN=Abcdef…               LEAK  npm_token=npm_abc…
LEAK  curl -u admin:hunter2 https://x            LEAK  TOKEN="abc def"
LEAK    "PASSWORD": "hunter2",                   LEAK  ssh-rsa AAAAB3Nza… (public key — fine to leak)
redact  password=hunter2 · export SECRET=hunter2 · secret_key=hunter2 · x-api-key: sk-ant-… · JWT · AKIA · ghp_ · xoxb · 40-hex
```
The 12 existing tests all use the bare `password=` / `token:` form, so they pass.

Fix (≈ 20 min): key pattern `\b([A-Za-z0-9_-]*(?:pass(?:word|wd)?|pwd|token|secret|api[_-]?key|access[_-]?key|private[_-]?key|credential)[A-Za-z0-9_-]*)`;
separator `(\s*["']?\s*[=:]\s*)`; value `("([^"]*)"|'([^']*)'|\S+)`; add `\b(?:sk|rk|pk)_(?:live|test)_[A-Za-z0-9]{8,}`,
`\bAIza[0-9A-Za-z_-]{20,}`, `\bnpm_[A-Za-z0-9]{20,}`, and `(://[^/\s:@]+:)[^@\s]+(@)` → `$1[redacted]$2`.
Add the 18 leaking lines above as tests. Keep `redactForAgent` the single choke point.

### F2. Bridge dies when the shell `cd`s into a path containing `%`
`packages/bridge/src/shell-integration.js:130` — lane C.

`decodeURIComponent(m[1])` on the OSC 7 body. zsh's `printf '\e]7;file://%s%s\a' "$HOST" "$PWD"`
emits `$PWD` raw (not percent-encoded), so a `%` that isn't a valid escape throws `URIError`, inside
`term.onData` → uncaught → process exit.

Measured (`scratchpad/bridge-crash.mjs`, real PTY, N=1): pair → `cd '/tmp/rokan 100%done'` →
`UNCAUGHT EXCEPTION: URIError: URI malformed` (exit 3). Also: `OscParser.feed('\x1b]7;file://mac/tmp/100%done\x07')` throws directly.

Fix: `try { decodeURIComponent } catch { use m[1] raw }` — or stop decoding, since nothing is encoded.

### F3. Bridge dies on the first reconnect after the shell exits
`packages/bridge/src/bridge.js:78-82, 126` — lane C.

`term.onExit` closes the client but keeps the server. The next tab pairs, `f.cols && f.rows` →
`term.resize()` on the dead PTY → `Error: ioctl(2) failed`, uncaught. `term.write` would do the same.

Measured (`scratchpad/bridge-probe2.mjs`, N=1): pair → `exit\r` → `{type:'exit',code:1}` → pair again →
`UNCAUGHT: Error: ioctl(2) failed` (exit 3).

Fix: after `onExit`, either respawn the shell (better demo: the tab shows "shell exited, restarting")
or set `dead = true` and answer new auth with `{type:'error', code:'shell_exited'}` then `process.exit(0)`.
Wrap `term.write`/`term.resize` in try/catch regardless.

### F4. Forge quoting bypass through ANSI-C `$'…'` strings — executes in zsh and bash
`apps/web/src/lib/webmcp/forge-spec.ts:170-196` (`substituteLine`) — lane C.

The scanner treats `$'` as an ordinary single quote. Inside `$'…'` the shell interprets `\'` as an
escaped quote, so the `'\''` rewrite terminates the string early. FORGE-PLAN §4.3/§6 claim the
substitution "neutralises `; | & $ …` in sh/bash/zsh".

Measured (`scratchpad/quote-probe.ts`, N=1 each): template `echo $'hello {{x}}'`, value
`a\'; touch <marker> #` → line `echo $'hello a\'\''; touch <marker> #'` → **marker created** under
`/bin/zsh` and `/bin/bash`. The five other contexts (`"…"`, `'…'`, bare with `$(…)`, backtick, `;`)
are correctly literal — the design is right, one quoting form is unmodelled.

Fix: treat `$'` (and `$"`) as an opening quote whose *close* rules differ: inside `$'…'` emit the value
with `\` → `\\` and `'` → `\'`; simpler and safer: reject templates that contain `$'` or `$"` at forge
time (`placeholder_in_quotes`-style error). Add the probe as a test. The keyboard still gates it — the
human sees the line — so P1, not P0; but do not ship the "neutralises" sentence until fixed.

### F5. `terminal_wait` never returns `unknown_proposal`; an unknown id waits 45 s and says `still_waiting`
`apps/web/src/lib/webmcp/register.ts:163-167` at HEAD — lane C. (FORGE-PLAN §3.4 lists the fix; the
in-flight `register.ts` may already carry it — verify with the step below when it lands.)

`proposals.wait()` returns `null` for an unknown id and `register.ts` maps every `null` to
`still_waiting`. `TerminalWaitResult` already types `unknown_proposal`.

Measured (CDP, HEAD build): `invoke terminal_wait {proposal_id:"p_does_not_exist"}` →
`{"status":"still_waiting","waited_ms":1}` — instantly, and again on every retry, forever.

Fix: `if (!store.has(id)) return { status: 'unknown_proposal' }` before waiting.

### F6. `why` is rendered unvalidated next to the command — bidi/control characters go straight to the prompt line
`apps/web/src/lib/webmcp/register.ts:79` (validation, lane C) · `TerminalTools.tsx:76-78` (render, lane Ay).

`command` is sanitised (ALIGNMENT row 1); `why` is only `.slice(0, 200)`. The same inline span
carries `command` + `← proposed: <why>`, so an RLO / ESC in `why` lands beside the command text.

Measured (CDP): `terminal_propose {command:"echo hi", why:"<U+202E> evil <U+001B>[31m why"}` →
accepted → the prompt line's innerText contains the raw U+202E and U+001B bytes right after
`echo hi← proposed:`. React escapes HTML so no XSS, but the spoofing surface ALIGNMENT closed for
`command` is open for `why`.

Fix: run `why` through the same C0/C1/`\p{Cf}` filter (reject or strip), and render it in its own
block-level element with `unicode-bidi: isolate`.

### F7. Bridge ledger: a client row can overwrite `seq`, `t`, `session`, `origin` and claim `kind:'executed'`
`packages/bridge/src/bridge.js:152-155` + `ledger.js:33` — lane C. (Complements Opus P0 #1; different bug.)

`ledger.append(kind, { origin: 'client', ...fields })` spreads the client's fields *after*
`origin`, and `append` spreads `...fields` *after* `seq/t/session/kind`. `protocol.js` accepts any
`row.kind`. So a page (or anything with the token) can write a row that says it is a bridge-originated
`executed` in another session — and `verifyLedger` stays `ok:true` because the row is signed as sent.

Measured (`scratchpad/bridge-probe.mjs`): client row `{kind:'executed', origin:'bridge', seq:1,
session:'sessB', t:'1999-…', command:'rm -rf /', exit_code:0}` → stored verbatim with `origin:"bridge"`,
`session:"sessB"`, `seq:1`; `verifyLedger('sessA')` → `{"ok":true}`.

Fix: in `bridge.js`, allowlist `row.kind` to `ClientLedgerKind` (`proposed|dismissed|screen_read|forged|invoked|…`) and
strip `seq,t,session,kind,prev,sig,origin` from `fields` before append; in `ledger.js`, spread
`...fields` first and reserved keys last. Add a smoke check.
