# Execution plan — "Compose the web, keep it as a tool" (COMPOSE-PLAN build)

Full spec, evidence and etiquette: `docs/COMPOSE-PLAN.md` (pushed, `6ede64f`). This file is the
build order with exact touch points. Repos: `~/dev/webmcp-private` (entry) and `~/dev/Rokan`
(engine; only wheels move over).

## Context
Seven research lanes (2026-08-29) showed the entry as-is is a strong top-10 but not #1: three
premises were stale (ChatGPT desktop *has* a terminal + actions; the Enter gate is the control the
labs measured at 93% blind approval and moved past; typed shell output is against the current), and
the one lane nobody occupies is **user-side composition of the web's tools, kept as a new WebMCP
tool**. Rokan `IDEA-LEDGER §S` had two finals (Forge-on-the-page vs terminal); this merges them:
terminal = vehicle, `rokan do` = consume-else-compile, forge composes `machine` + `web:native` +
`web:compiled` steps, tools are kept. **Tier 0 measured feasible:** allbirds.com exposes 10 native
WebMCP tools to the CDP `WebMCP` domain from rokan-do's own Chromium (FIELD-NOTES T5).
Criteria bind verbatim: full product not PoC; Impact "based on what's demonstrated".
Target submit Tue 09-01; freeze Mon 08-31 12:00 PT; hard fallback Wed 09-02 evening.

```
                │          1 call) → planned(1 call) → refused          ← service.perform()   │
                │  browser = rokan-mcp daemon (+2 verbs: webmcp_list / webmcp_invoke via CDP) │
                └───────────────────────────────────────────────────────────────────────────┘
```
- **Terminal stays entirely** — it is the *trace* and the substrate: every step (machine or web) runs there, visibly, with honest exit/ms; ghost text + Enter stay as the mechanism for unforged steps and for every CONSEQUENTIAL step. Nothing in TERMINAL-PLAN is undone. What changes is only the *pitch*: it is no longer the headline.
- **Forge stays entirely** — same contract (`{name, description, commands[≤5], params[≤6], kind}`), same hash/budget/queue/stats/pin/evict/restore. A "composed tool" is just a forged tool whose `commands[]` contain `rokan do …` lines; nothing new is needed for composition itself. Two additive fields (`provenance[]`, `calls_last`) and one new property (kept).
- **rokan do gains one rung (native)** and one marker in its result line; everything else in Rokan is untouched. The bridge parses the marker; the page shows it. That is the whole connection: `rokan do` prints → bridge attributes (`isRokanCommand`) → `terminal_wait.rokan` → forge stats → chips + `forge_list`.
- **Judge mode unchanged:** the container keeps today's wheels; an unseeded native step there prints Rokan's real message `abstained_planner_unavailable` ("could not reach its model provider" — no key, no browser; `render_do.py` L28–34, FIELD-NOTES R6) — README, DEMO and the tour say *exactly that*, never a string no code path emits (reviewer P1). Compiled steps replay. No sandbox image deploy this sprint (a wheel bump for a nicer `ROKAN_NO_BROWSER` reason is allowed only if it lands before the Mon 12:00 freeze and the rollout is verified applied — otherwise the honest message stands).
- **Why this shape and not another:** it keeps browsing out of the WebMCP layer (the DOM kill-shot), keeps every tool inert, and makes "consume native first" a measured fact inside the same engine that compiles — one product, one page, one ledger.

## 1. Tier 0 in rokan-do (Rokan repo) — exact touch points (design decided: daemon verbs, not a second browser)
**Architecture facts that bind:** the browser is the daemon (`packages/rokan-mcp/src/rokan_mcp/_daemon.py`, launch at L1768 `launch_persistent_context(channel="chrome")`, fallback bundled Chromium L1778, `_launch_args()` just above; `_DISPATCH` table L3514; `_dispatch()` L3568 serialises under `state.lock`); `scripts/rokan_browser_daemon.py` is a byte-identical copy the gate pins (`regression_gate.py` step "daemon-copy-in-sync") — **every daemon edit is applied to both files**. rokan-do reaches it via `rokan_agent.core.proven.browser.session_for(host)` (`executor.py` L102/L122/L267; single seam L255). The speed ladder is `service.py:perform()` L205 (`Performed.path` = `compiled|replayed|planned`, L55–75; `_label_of` L165 → `verified|self_reported|refused`). No CDP session exists anywhere today.

- **1a. Daemon verbs (both files, same diff):** add `webmcp_list {url}` and `webmcp_invoke {url, tool, input}` to `_DISPATCH` (L3514). **Implementation (order matters — reviewer P0):** `cdp = await context.new_cdp_session(page)`; `WebMCP.enable`; **then** `_cmd_navigate(url, reload=True)` — the daemon's `navigate` is idempotent (`_daemon.py` L1846–1857 returns `already_here` with no load on a revisited URL, which is exactly the second-run case) so the verb must force a load; collect `toolsAdded` until the requested tool appears or 3 s quiet; **keep the CDP session attached and cache `tools` per tab until the next navigation** (so `webmcp_invoke` on a warm tab does not pay navigate + 3 s; `frameId` comes from the cached list). Return `[{name, description, inputSchema, annotations, frameId}]`; invoke = `WebMCP.invokeTool {frameId, toolName, input}` → await `toolResponded {status, output}` (**10 s** timeout — `_dispatch` holds the global lock for the whole handler, L3574; a long invoke stalls `watch`) → `{status, output, ms}`. Add `"--enable-features=WebMCP"` to `_launch_args()` (L1167). Measured pattern to copy: `evals/diagnostics/tier0-probe.py` enables *before* `goto`. Daemon unit tests: verbs with a fake CDP; **"enable after load yields no tools ⇒ reload path"**.
- **1b. rokan-do rung** — new `packages/rokan-do/src/rokan_do/native.py`: `list_tools(site)`, `invoke(site, tool, input)` (via the daemon verbs through the `executor.py` L255 seam), `select_tool(said, tools) -> {tool, input}` (one model call via the existing `cascade.run` ladder with a tool-list prompt; **never sees the DOM**), `NativeOp` record. Wire into `service.perform()`:
  1. before L246 `memory.recall`: if a **native op** exists for `(host, task_class, said)` → `invoke` → `verify()` (`verify.py` L1358, `value_present` against `output`) → `Performed(path="native", verification=…)`, `record_use(path="native")`, `model_calls=0`.
  2. after the compiled/replayed branches fail to answer and **before** the planned tail (L540): `list_tools(site)`; if ≥ 1 `readOnly` tool → `select_tool` (1 call) → `invoke` → `verify` → `memory.remember` a native op (plan blob `{kind:"native", tool, input_template, schema_hash}`) → `Performed(path="native")`, `model_calls=1`. Tools without `readOnly:true` are skipped unless `allow_write=True` (never set by the terminal).
  3. **Retire** (v1 = mark only): when native tools are listed for a host that has compiled/replayed ops, set `operation.retired_at` via `memory.retire` (L985) for those keys and narrate "native tools found; compiled op retired". (Demo says it; ledger shows it.)
- **1c. Grammar + JSON:** `packages/rokan-agent/src/rokan_agent/adapters/cli/render.py` L80–88: when `transport_used == "native"` append `  ⚙ native:<host>:<tool>` **after** the ms tail (and after `⚡`), so the bridge regex can `$`-anchor the provenance tokens behind the number — the answer text precedes the tail and is untrusted (a site could return `   ⚙ native:x:get_cart   1ms` inside its output; reviewer P1); **strip `⚙` and `⚡` from `result.data` in `render`** before printing. Keep `⚡` for any 0-call answer (native replay included). `cli.py` `run` (L304–325) gains `--json` → prints `mcp._result_json(result, speed)` (L219) plus `native:{site,tools}` and `model_calls`. `mcp.py` `tool_do` passes `path="native"` through (`speed` doc L8–9/L136 updated).
- **1d. Memory:** no schema change — native ops use the existing `operation` row with the plan blob carrying `kind:"native"` and `schema_hash`; `recall` (L650) already routes by host/task_class/`answers()`; add `_is_native(plan)` guard so `run_fast`/replay branches skip native blobs.
- **1e. Tests (sync pytest, `asyncio.run`, no pytest-asyncio):** `packages/rokan-do/tests/test_native.py` (≥ 10): fake daemon client (tools listed / none / late / `Error` / `Canceled`); readOnly gate; native replay = 0 calls; schema_hash change ⇒ re-select (1 call); retire marks compiled ops; grammar round-trip through the bridge regex text; `--json` fields. Daemon unit test for the two verbs with a fake `cdp` (mirror an existing `_daemon` unit test). Mutation report in prose (Rokan convention): ≥ 3 mutants per guard, all killed.
- **1f. Measurements:** `docs/measurements/2026-08-29-tier0.md` in the template of `2026-08-28-ambiguity-rung.md` — pre-registered before any model call: *Q1 does `search_catalog("wool runners")` on allbirds.com return ≥ 1 product via the daemon? ## 10a. The testing discipline (the Tavril rule, made mechanical — applies to every line in this plan)
**Principle:** nothing is believed until the smallest piece it can be proven at is proven, then everything it touches is re-proven, then the whole is proven at the boundary the judge touches. "I think it works" is not a state.

**The loop for every change (FORGE-PLAN §16, restated as commands):**
1. **Green before** — run the existing gate for the repo you're in and paste the numbers into the commit body. Never build on red.
2. **Failing test first** — write the unit/eval case; run it; it must fail *for the right reason* (say so in the commit).
3. **One change** — one function / one verb / one field / one component.
4. **Prove it** — the new test passes; `tsc --noEmit` / `ruff` + `mypy` clean.
5. **Re-prove the neighbours** — every caller/callee/contract-sharer of the changed piece (map: `schemas.ts`→register/forge/Panes/harness; `protocol.ts`↔`bridge/protocol.js`; `rokan-trailer.js`→bridge.js→adapter.ts→register.ts→forge.ts; `service.perform`→mcp.py/cli.py/render.py/tests).
6. **Prove the whole** — the full gate of that repo, once, batched (no loops).
7. **Prove it for real** — the boundary the judge touches: headless CDP eval for any tool change; real PTY smoke for any bridge change; headed Chrome screenshot for any UI change; live judge URL for anything judge-visible; **the app opens** (`curl` 200 on `/` + a headless case that registers 6 tools) before *every* push.
8. **Record** — numbers in the commit message and PROGRESS. A claim without the command and its output is not a claim.
9. **Regression** → stop feature work, root-cause (`systematic-debugging`), add the regression test, then continue. 3 strikes → write the state down and move on.

## 16. Self-evaluation and the manual regime (binding on every engineer, reviewer and subagent)
**Self-evaluation against this document.** Every engineer session, every reviewer, every subagent that builds, tests or reviews anything in this sprint opens this file and `docs/COMPOSE-PLAN.md` first and, before reporting "done" on any item, answers in writing (commit body or PROGRESS): *which section of the plan this satisfies · which ladder rungs (L0–L8) were run, with the command and its numbers · which of C1–C10 it touches and whether the evidence moved · what was **not** done and why.* A report without those four answers is not accepted; a reviewer who cannot point to the plan section is not reviewing. Subagents receive this file's path in their brief; their green unit run is never verification — the owner re-runs the integration suites (memory: `subagent-verification`).

**The manual regime — from the first build, cumulative, never skipped.** Automated ladders prove pieces; the manual regime proves the *stack still stands* as builds pile up. After **every merge to `main`** (both repos), the owner runs by hand — real Chrome, then the ChatGPT desktop browser when the change is judge-visible — the **Build Manual Checklist**, and logs one row per build hash in `docs/PROGRESS.md` → "Manual runs" (hash · date · who · steps green/red · screenshot path):
1. `curl` 200 on the live URL and the Worker health.
2. Page loads cold in a clean profile: hero, tools pane (6), terminal, ledger — no console errors (DevTools).
3. Try it now → sandbox pairs → `propose ls` → Enter → `exit 0 · N ms` in the ledger.
4. Share screen on → `terminal_read_screen` returns redacted lines; off → `{shared:false}`.
5. Forge from history → card → Approve → tools 6 → 7 → agent calls it → ghost → Enter → row.
6. `rokan do` seeded question → `⚡ … 0 calls` (and, on the builder Mac, a native step → `⚙ native`).
7. Reload → restore card → approve → same hash back.
8. Codex (MCP relay) lists the forged tool and calls it → ghost → Enter.
9. Every failure state reachable on purpose: expired link, busy tab, unauthorized, 429 copy, `abstained_planner_unavailable`, restore-hash mismatch.
10. `npx rokan-terminal` (or the clone + node form) from a clean directory pairs and runs step 3.
The checklist **grows** with every feature (a new feature adds its line; nothing is removed), so a regression in an old feature is caught the same day it is introduced — never discovered as "one big pile of non-functional code" at the end. The final manual regime before submission is the full checklist, run from the very beginning, in ChatGPT's browser, by hand, recorded.
